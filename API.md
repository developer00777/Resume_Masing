## 1. Base URL & Auth

```
Base URL: https://resume-masker-production.up.railway.app
```

| Header | Used by | Current live behavior |
|---|---|---|
| `X-API-Key` | `/mask`, `/mask/batch`, `/mask/inline`, `/watermark/upload`, `/clients/self-register` | **Enforced** — 401 without it |
| `X-Admin-API-Key` | `GET/PUT/DELETE /admin/clients` | **Enforced** — 401 without it (503 only if `ADMIN_API_KEY` were unset, which it isn't) |

`GET /health` and `GET /popup` never require auth.

`status: "error"` responses are returned as **HTTP 200** with a
human-readable `detail` string — check the `status` field, not the HTTP
status code, for success/failure (keeps Flow/Apex error handling simple).
Exceptions: FastAPI validation errors (HTTP 422, e.g. missing required
field) and the two auth headers above (401) do use non-200 codes.

## 2. Environment variables — full reference

### Salesforce auth (pick ONE mode) — currently: Mode A

| Var | Mode | Set on Railway today? | Notes |
|---|---|---|---|
| `SF_USERNAME` | A / B | ✅ yes | Integration user's login, not a personal account |
| `SF_PASSWORD` | A / B | ✅ yes | That user's password |
| `SF_SECURITY_TOKEN` | A | ✅ yes | Setup → Reset My Security Token |
| `SF_DOMAIN` | A / B | ✅ yes (`test`) | Currently pointed at a **sandbox** — `login` (prod, default) / `test` (sandbox) / a My Domain host |
| `SF_CONSUMER_KEY` | B | not set | Connected App Consumer Key — presence of this switches the service from mode A to mode B |
| `SF_CONSUMER_SECRET` | B | not set | Connected App Consumer Secret |
| `SF_CLIENTS_JSON` | C | not set | JSON object, static multi-org registry — see below. Mutually compatible with A/B (C is selected per-request via `client_key`, not globally) |

**⚠️ Sandbox vs. production:** `SF_DOMAIN=test` means `/mask` currently reads
and writes against a **sandbox** org, not production. If the real Job
Applicant records live elsewhere, `/mask` will authenticate fine but query
the wrong org (clean "no resume found" errors, not auth errors — easy to
mistake for a data problem). Confirm which org should be live before
directing real traffic at this deployment.

**Mode A** (current): `SF_USERNAME` + `SF_PASSWORD` + `SF_SECURITY_TOKEN` + `SF_DOMAIN`.

**Mode B** (Connected App, single org): adds `SF_CONSUMER_KEY` + `SF_CONSUMER_SECRET` on top of A's username/password. Not in use today.

**Mode C** (multi-org, OAuth2 Client Credentials — for onboarding additional client orgs without touching Mode A):

```json
SF_CLIENTS_JSON={"00D5f000000ABCDEAU":{"client_id":"3MVG9...","client_secret":"64585...","token_url":"https://acme.my.salesforce.com/services/oauth2/token","instance_url":"https://acme.my.salesforce.com"}}
```

Keyed by `client_key`, by convention the org's own Salesforce Organization
Id. Callers pass `client_key` in the request body to select which org's
creds to use. Static — requires a redeploy to add/change an entry. For
dynamic registration without a redeploy (what's actually configured today),
use the Postgres-backed registry below via `/clients/self-register`; DB
entries win over `SF_CLIENTS_JSON` entries on `client_key` collision.

### Dynamic client-org registry (Postgres) — set on Railway today

| Var | Set on Railway today? | Notes |
|---|---|---|
| `DATABASE_URL` | ✅ yes (`${{Postgres.DATABASE_URL}}`) | Auto-injected by the linked Postgres plugin service. |
| `CLIENT_SECRET_ENCRYPTION_KEY` | ✅ yes | Symmetric key (Fernet) encrypting `client_secret` before it's written to Postgres. Generate: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` |

Both being set means `/clients/self-register` and `/admin/clients` are fully
functional today — confirmed live (see §0).

### Server / Railway

| Var | Required? | Notes |
|---|---|---|
| `PORT` | no | Railway sets this automatically. Only set manually for local Docker (`docker run -e PORT=8000 ...`). |

### Endpoint auth — both set on Railway today

| Var | Set on Railway today? | Notes |
|---|---|---|
| `MASK_API_KEY` | ✅ yes | Shared secret for `X-API-Key` on `/mask`, `/mask/batch`, `/mask/inline`, `/watermark/upload`, `/clients/self-register`. `/popup` auto-templates it into its own `fetch()` calls. Request the value through a private channel — not written here. |
| `ADMIN_API_KEY` | ✅ yes | Separate, higher-privilege secret from `MASK_API_KEY` for `X-Admin-API-Key` on `/admin/clients`. Also requested privately. |

## 3. Endpoints

### `GET /health` — unauthenticated

```json
{ "status": "ok", "salesforce_configured": true, "client_keys": [], "registry_backend": "db+env" }
```
(exact live response as of this writing)

| Field | Meaning |
|---|---|
| `salesforce_configured` | `true` if at least one auth mode (A/B/C) has all required vars present |
| `client_keys` | Sorted list of registered multi-org `client_key`s (merged `SF_CLIENTS_JSON` + Postgres) — empty today, Mode A is single-org |
| `registry_backend` | `"db+env"` if `DATABASE_URL` is set (dynamic registration available), else `"env-only"` |

### `POST /mask/inline` — needs no Salesforce config, works everywhere

Pure bytes-in, bytes-out. Recommended for callers (e.g. Apex) that
fetch/write Salesforce records themselves and just want the masking
transform.

**Request:**
```json
{
  "resume_base64": "<base64 PDF>",
  "mask_strings": ["Jane Roe", "+1 555 010 0199", "jane.roe@example.com"],
  "watermark_text": "CONFIDENTIAL",
  "watermark_base64": "<base64 PNG/JPEG, optional>"
}
```

| Field | Required | Notes |
|---|---|---|
| `resume_base64` | yes | Source PDF, base64-encoded |
| `mask_strings` | no | Exact PII strings to redact. Falls back to a regex email/phone scan of the PDF text if omitted — less precise, no name detection |
| `watermark_text` | no | Fallback text watermark. Default `"CONFIDENTIAL"` |
| `watermark_base64` | no | Client logo image, base64 |

**Response:**
```json
{ "status": "ok", "masked_pdf_base64": "<base64 masked PDF>", "redacted_regions": 3, "watermark_used": "image:inline_base64", "detail": null }
```

Verified live: PII (name/phone/email) is true-redacted (glyphs removed, not
covered), non-PII content (experience, marks/%) is preserved, and the
watermark is stamped.

### `POST /mask` — mask one candidate, fully working live

```json
{
  "job_applicant_id": "a0X000000000001",
  "account_id": "001XXXXXXXXXXXXAAA",
  "mask_strings": ["John Doe", "+91 98765 43210", "john.doe@example.com"],
  "watermark_text": "CONFIDENTIAL",
  "watermark_base64": "<base64 PNG/JPEG, optional>",
  "client_key": "00D5f000000ABCDEAU"
}
```

Fetches the resume from Salesforce, resolves the client watermark, redacts,
uploads the masked PDF back as a new `ContentVersion`. `client_key` is
optional and only relevant if Mode C orgs get registered — omit it to use
the live Mode A connection. Full field reference in
`SALESFORCE_INTEGRATION.md` §4.

**Response:**
```json
{ "status": "ok", "masked_content_version_id": "068000000000001AAA", "redacted_regions": 3, "watermark_used": "image:account_001XXXXXXXXXXXXAAA", "detail": null }
```

### `POST /mask/batch` — bulk version of `/mask`

```json
{
  "client_key": "00D5f000000ABCDEAU",
  "items": [
    { "job_applicant_id": "a0X000000000001" },
    { "job_applicant_id": "a0X000000000002" }
  ]
}
```

Max 200 items. One shared Salesforce session per call. One item's failure
doesn't abort the rest:

```json
{ "status": "ok", "succeeded": 1, "failed": 1, "results": [ { "job_applicant_id": "a0X000000000001", "result": {"status":"ok", "masked_content_version_id":"068..."} }, { "job_applicant_id": "a0X000000000002", "result": {"status":"error","detail":"No resume found..."} } ] }
```

### `POST /watermark/upload` — set a client's logo (multipart/form-data)

```
account_id=<Salesforce Account Id>
file=<PNG/JPEG>
client_key=<optional, multi-org only>
```

Stores the image as a Salesforce File titled `ResumeWatermark` on that
Account — every later `/mask` call for that account auto-resolves it.

### `POST /clients/self-register` — register a new org (Mode C)

```json
{
  "client_key": "00D5f000000ABCDEAU",
  "client_id": "<Connected App Consumer Key>",
  "client_secret": "<Connected App Consumer Secret>",
  "token_url": "https://yourorg.my.salesforce.com/services/oauth2/token",
  "instance_url": "https://yourorg.my.salesforce.com"
}
```

Gated by `X-API-Key` (not `X-Admin-API-Key`). Create-only — a second call
for an already-registered `client_key` returns an error instead of
overwriting.

### `GET/PUT/DELETE /admin/clients` — admin registry management

Gated by `X-Admin-API-Key` (separate from `MASK_API_KEY`).

```
GET    /admin/clients                     — list all registered orgs (no secrets returned)
PUT    /admin/clients/{client_key}        — register or rotate credentials (allow_overwrite=true)
DELETE /admin/clients/{client_key}        — deregister a DB-managed org
```

### `GET /popup` — embeddable HTML UI

Ready-made "Connect Your Org" + watermark upload + Mask button page for a
Lightning Component / iframe embed. Auto-templates `MASK_API_KEY` into its
own `fetch()` calls.

## 4. Error reference

All error responses share this shape (HTTP 200, `status: "error"`):

| `detail` pattern | Cause | Fix |
|---|---|---|
| `Salesforce credentials not configured.` | No auth mode configured at all | N/A on this deployment — Mode A is live |
| `Invalid Salesforce Id for ...` | Malformed/wrong-length Id | Check the caller's merge field |
| `No resume found for Job Applicant '...'.` | No PDF attached to that record | Confirm the resume was uploaded, and check §2's sandbox-vs-prod note |
| `No PII strings to mask.` | Neither `mask_strings` nor the regex fallback found anything | Pass explicit `mask_strings` |
| `Unknown client_key '...'. Configured: [...]` | `client_key` passed but not registered | Register via `/clients/self-register`, or omit `client_key` to use the live Mode A connection. Fixed 2026-08-27 to surface this specific message instead of the generic one above (§0). |
| `watermark_base64 is not valid base64.` | Malformed inline watermark | Check the encoding |
| `resume_base64 is not valid base64.` | Malformed inline resume (`/mask/inline` only) | Check the encoding |
| `This org is already registered...` | `/clients/self-register` called twice | Rotate via `/admin/clients` instead |
| `Missing or invalid X-Admin-API-Key.` | Wrong/missing admin key | Request the key privately |
| `Missing or invalid X-API-Key.` | Wrong/missing `X-API-Key` | Request the key privately |

## 5. Verification tooling

```
tests/e2e_live_regression.ps1 -BaseUrl <url> -ApiKey <key> -AdminApiKey <key>
```

Reusable regression suite — run it after every deploy. Covers health,
auth enforcement, the full `/mask/inline` pipeline (real PDF, real
redaction, real watermark), the SOQL-injection guard, batch size limits,
watermark content-type validation, and the self-register/admin lifecycle
(creates and deletes its own test data — leaves no residue). `-ApiKey` /
`-AdminApiKey` are optional; omit to test only the unauthenticated paths.

Local Docker (mirrors the Dockerfile Railway builds from):

```bash
docker build -t resume-masking:local .
docker run -d --name resume-masking-pg -e POSTGRES_PASSWORD=devpass -e POSTGRES_DB=resume_masking -p 55432:5432 postgres:16-alpine
docker run -d --name resume-masking-app -p 8080:8000 \
  -e DATABASE_URL=postgresql://postgres:devpass@<pg-container>:5432/resume_masking \
  -e SF_USERNAME=... -e SF_PASSWORD=... -e SF_SECURITY_TOKEN=... -e SF_DOMAIN=... \
  -e MASK_API_KEY=... -e ADMIN_API_KEY=... -e CLIENT_SECRET_ENCRYPTION_KEY=... \
  resume-masking:local
```

`python -m pytest tests/ -v` for the unit suite (68/68 as of this writing).
