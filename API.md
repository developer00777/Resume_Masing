# API Documentation — Resume Masking Service

Endpoint reference + environment-variable reference for the FastAPI service in
`app/server.py`. For the Salesforce-team-facing integration walkthrough (Apex
snippets, Notes & Attachments flow), see `SALESFORCE_INTEGRATION.md` — this
doc is the general API + config reference.

Interactive schema (auto-generated by FastAPI, always in sync with the code):
`GET /docs` (Swagger UI) or `GET /redoc` on any running deployment.

## 0. Current Railway deployment status

**As of now, the only environment variable set on the Railway service is:**

```
DATABASE_URL="${{Postgres.DATABASE_URL}}"
```

This is Railway's reference-variable syntax — it's auto-injected because a
Postgres plugin service is linked to this service. **No other variable is
set yet** (no `SF_*`, no `MASK_API_KEY`, no `ADMIN_API_KEY`, no
`CLIENT_SECRET_ENCRYPTION_KEY`).

Verified locally by running the service against a fresh Postgres with
literally only `DATABASE_URL` set (nothing else in the environment) — this is
the **actual current behavior** of the live deployment, not a guess:

| Endpoint | Behavior today |
|---|---|
| `GET /health` | `{"status":"ok","salesforce_configured":false,"client_keys":[],"registry_backend":"db+env"}` |
| `POST /mask/inline` | **Works fully.** No Salesforce needed — pure bytes-in/bytes-out. This is the only endpoint that does real work right now. |
| `POST /mask`, `POST /mask/batch` | `{"status":"error","detail":"Salesforce credentials not configured."}` (HTTP 200) |
| `POST /watermark/upload` | `{"status":"error","detail":"Salesforce not configured."}` (HTTP 200) |
| `POST /clients/self-register` | `{"status":"error","detail":"CLIENT_SECRET_ENCRYPTION_KEY is not set. Generate one with: python -c \"from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())\""}` (HTTP 200) — Postgres itself is reachable (`registry_backend: db+env`), but the service refuses to write a client secret it can't encrypt. |
| `GET/PUT/DELETE /admin/clients` | **HTTP 503** `{"detail":"Admin API not configured (ADMIN_API_KEY unset)."}` — fails closed by design (see §2). |

**⚠️ Security note:** `MASK_API_KEY` is also unset, so every write endpoint
(`/mask`, `/mask/batch`, `/mask/inline`, `/watermark/upload`,
`/clients/self-register`) is currently **unauthenticated** — anyone with the
Railway URL can call them. Fine for initial pilot/testing; set
`MASK_API_KEY` before this URL is shared with the client's Salesforce org or
posted anywhere less trusted than this conversation.

**To reach full functionality**, add on Railway (see §2 for what each does
and how to generate it):

```
SF_USERNAME=...            # or SF_CLIENTS_JSON for multi-org
SF_PASSWORD=...
SF_SECURITY_TOKEN=...
SF_DOMAIN=login
MASK_API_KEY=...           # openssl rand -hex 32
ADMIN_API_KEY=...          # openssl rand -hex 32, separate from MASK_API_KEY
CLIENT_SECRET_ENCRYPTION_KEY=...   # only needed if you'll use /clients/self-register or /admin/clients
```

None of these are required for `/mask/inline` to work — that endpoint is
already fully usable today with zero additional configuration.

## 1. Base URL & Auth

```
Base URL: https://<your-railway-app>.up.railway.app
```

| Header | Used by | Behavior when unset |
|---|---|---|
| `X-API-Key` | `/mask`, `/mask/batch`, `/mask/inline`, `/watermark/upload`, `/clients/self-register` | **Unenforced** (open) — see the security note in §0 |
| `X-Admin-API-Key` | `GET/PUT/DELETE /admin/clients` | **Fails closed** — 503, route unusable until set |

`GET /health` and `GET /popup` never require auth.

`status: "error"` responses are returned as **HTTP 200** with a
human-readable `detail` string — check the `status` field, not the HTTP
status code, for success/failure (keeps Flow/Apex error handling simple).
Exceptions: FastAPI validation errors (HTTP 422, e.g. missing required
field) and the two auth headers above (401 / 503) do use non-200 codes.

## 2. Environment variables — full reference

### Salesforce auth (pick ONE mode)

| Var | Mode | Required? | Notes |
|---|---|---|---|
| `SF_USERNAME` | A / B | yes (for A/B) | Integration user's login, not a personal account |
| `SF_PASSWORD` | A / B | yes (for A/B) | That user's password |
| `SF_SECURITY_TOKEN` | A | yes (for A) | Setup → Reset My Security Token |
| `SF_DOMAIN` | A / B | no | `login` (default, prod) / `test` (sandbox) / a My Domain host |
| `SF_CONSUMER_KEY` | B | yes (for B) | Connected App Consumer Key — presence of this switches the service from mode A to mode B |
| `SF_CONSUMER_SECRET` | B | yes (for B) | Connected App Consumer Secret |
| `SF_CLIENTS_JSON` | C | yes (for C) | JSON object, static multi-org registry — see below. Mutually compatible with A/B (C is selected per-request via `client_key`, not globally) |

**Mode A** (simplest, single org): `SF_USERNAME` + `SF_PASSWORD` + `SF_SECURITY_TOKEN` + optional `SF_DOMAIN`.

**Mode B** (Connected App, single org): adds `SF_CONSUMER_KEY` + `SF_CONSUMER_SECRET` on top of A's username/password.

**Mode C** (multi-org, OAuth2 Client Credentials — recommended for multiple client orgs):

```json
SF_CLIENTS_JSON={"00D5f000000ABCDEAU":{"client_id":"3MVG9...","client_secret":"64585...","token_url":"https://acme.my.salesforce.com/services/oauth2/token","instance_url":"https://acme.my.salesforce.com"}}
```

Keyed by `client_key`, by convention the org's own Salesforce Organization
Id. Callers pass `client_key` in the request body to select which org's
creds to use. Static — requires a redeploy to add/change an entry. For
dynamic registration without a redeploy, see the Postgres-backed registry
below; DB entries win over `SF_CLIENTS_JSON` entries on `client_key`
collision.

### Dynamic client-org registry (Postgres) — optional

| Var | Required? | Notes |
|---|---|---|
| `DATABASE_URL` | no | **Currently the only var set on Railway.** Auto-injected by linking a Postgres service (`${{Postgres.DATABASE_URL}}`). If unset, the service behaves exactly as if the whole DB-backed registry didn't exist — `SF_CLIENTS_JSON`-only. |
| `CLIENT_SECRET_ENCRYPTION_KEY` | only if `DATABASE_URL` is set AND a client actually gets registered | Symmetric key (Fernet) used to encrypt `client_secret` before it's written to Postgres — never stored in plaintext. Generate: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` |

With only `DATABASE_URL` set (today's state), `registry_backend` reports
`"db+env"` (Postgres is reachable) but `/clients/self-register` and
`PUT /admin/clients/{key}` will still fail until
`CLIENT_SECRET_ENCRYPTION_KEY` is also set — the service refuses to persist
an unencryptable secret rather than silently storing plaintext.

### Server / Railway

| Var | Required? | Notes |
|---|---|---|
| `PORT` | no | Railway sets this automatically. Only set manually for local Docker (`docker run -e PORT=8000 ...`). |

### Endpoint auth

| Var | Required? | Default when unset | Notes |
|---|---|---|---|
| `MASK_API_KEY` | recommended | **Unenforced** (open) | Shared secret for `X-API-Key` on `/mask`, `/mask/batch`, `/mask/inline`, `/watermark/upload`, `/clients/self-register`. `/popup` auto-templates it into its own `fetch()` calls once set. Generate: `openssl rand -hex 32` |
| `ADMIN_API_KEY` | required to use `/admin/clients` at all | **Fails closed (503)** | Separate, higher-privilege secret from `MASK_API_KEY` for `X-Admin-API-Key` on `/admin/clients`. Deliberately fails closed (unlike `MASK_API_KEY`) since it can register/rotate/remove any org's credentials. Generate: `openssl rand -hex 32` |

## 3. Endpoints

### `GET /health` — unauthenticated

```json
{ "status": "ok", "salesforce_configured": false, "client_keys": [], "registry_backend": "db+env" }
```

| Field | Meaning |
|---|---|
| `salesforce_configured` | `true` if at least one auth mode (A/B/C) has all required vars present |
| `client_keys` | Sorted list of registered multi-org `client_key`s (merged `SF_CLIENTS_JSON` + Postgres) |
| `registry_backend` | `"db+env"` if `DATABASE_URL` is set (dynamic registration available), else `"env-only"` |

### `POST /mask/inline` — works today with zero Salesforce config

The only endpoint that needs no Salesforce setup at all — pure bytes-in,
bytes-out. Recommended for callers (e.g. Apex) that fetch/write Salesforce
records themselves and just want the masking transform.

**Request:**
```json
{
  "resume_base64": "<base64 PDF>",
  "mask_strings": ["Jane Roe", "+1 555 010 0199", "jane.roe@example.com"],
  "watermark_text": "CONFIDENTIAL",
  "watermark_base64": "<base64 PNG/JPEG, optional>"
}
```

| Field | Required | Notes |
|---|---|---|
| `resume_base64` | yes | Source PDF, base64-encoded |
| `mask_strings` | no | Exact PII strings to redact. Falls back to a regex email/phone scan of the PDF text if omitted — less precise, no name detection |
| `watermark_text` | no | Fallback text watermark. Default `"CONFIDENTIAL"` |
| `watermark_base64` | no | Client logo image, base64 |

**Response:**
```json
{ "status": "ok", "masked_pdf_base64": "<base64 masked PDF>", "redacted_regions": 3, "watermark_used": "image:inline_base64", "detail": null }
```

Verified live (this exact response shape, against a real generated PDF, on
this deployment's current config): PII (name/phone/email) is true-redacted
(glyphs removed, not covered), non-PII content (experience, marks/%) is
preserved, and the watermark is stamped.

### `POST /mask` — mask one candidate, requires Salesforce config

```json
{
  "job_applicant_id": "a0X000000000001",
  "account_id": "001XXXXXXXXXXXXAAA",
  "mask_strings": ["John Doe", "+91 98765 43210", "john.doe@example.com"],
  "watermark_text": "CONFIDENTIAL",
  "watermark_base64": "<base64 PNG/JPEG, optional>",
  "client_key": "00D5f000000ABCDEAU"
}
```

Fetches the resume from Salesforce, resolves the client watermark, redacts,
uploads the masked PDF back as a new `ContentVersion`. See §0 — returns
`{"status":"error","detail":"Salesforce credentials not configured."}` until
an auth mode is configured. Full field reference in `SALESFORCE_INTEGRATION.md` §4.

**Response:**
```json
{ "status": "ok", "masked_content_version_id": "068000000000001AAA", "redacted_regions": 3, "watermark_used": "image:account_001XXXXXXXXXXXXAAA", "detail": null }
```

### `POST /mask/batch` — bulk version of `/mask`

```json
{
  "client_key": "00D5f000000ABCDEAU",
  "items": [
    { "job_applicant_id": "a0X000000000001" },
    { "job_applicant_id": "a0X000000000002" }
  ]
}
```

Max 200 items. One shared Salesforce session per call. One item's failure
doesn't abort the rest:

```json
{ "status": "ok", "succeeded": 1, "failed": 1, "results": [ { "job_applicant_id": "a0X000000000001", "result": {"status":"ok", "masked_content_version_id":"068..."} }, { "job_applicant_id": "a0X000000000002", "result": {"status":"error","detail":"No resume found..."} } ] }
```

### `POST /watermark/upload` — set a client's logo (multipart/form-data)

```
account_id=<Salesforce Account Id>
file=<PNG/JPEG>
client_key=<optional, multi-org only>
```

Stores the image as a Salesforce File titled `ResumeWatermark` on that
Account — every later `/mask` call for that account auto-resolves it.
Requires Salesforce config (same as `/mask`).

### `POST /clients/self-register` — register a new org (Auth mode C)

```json
{
  "client_key": "00D5f000000ABCDEAU",
  "client_id": "<Connected App Consumer Key>",
  "client_secret": "<Connected App Consumer Secret>",
  "token_url": "https://yourorg.my.salesforce.com/services/oauth2/token",
  "instance_url": "https://yourorg.my.salesforce.com"
}
```

Gated by `X-API-Key` (not `X-Admin-API-Key`). Create-only — a second call
for an already-registered `client_key` returns an error instead of
overwriting. Requires `DATABASE_URL` **and** `CLIENT_SECRET_ENCRYPTION_KEY`
(see §0 — currently fails on this deployment for the second reason).

### `GET/PUT/DELETE /admin/clients` — admin registry management

Gated by `X-Admin-API-Key` (separate from `MASK_API_KEY`, fails closed if
unset — currently 503 on this deployment).

```
GET    /admin/clients                     — list all registered orgs (no secrets returned)
PUT    /admin/clients/{client_key}        — register or rotate credentials (allow_overwrite=true)
DELETE /admin/clients/{client_key}        — deregister a DB-managed org
```

### `GET /popup` — embeddable HTML UI

Ready-made "Connect Your Org" + watermark upload + Mask button page for a
Lightning Component / iframe embed. Auto-templates `MASK_API_KEY` into its
own `fetch()` calls once that var is set. Works today (renders), but its
buttons hit the same errors listed in §0 until Salesforce/admin vars are set.

## 4. Error reference

All error responses share this shape (HTTP 200, `status: "error"`):

| `detail` pattern | Cause | Fix |
|---|---|---|
| `Salesforce credentials not configured.` | No auth mode configured | Set mode A/B/C vars (§2) |
| `Invalid Salesforce Id for ...` | Malformed/wrong-length Id | Check the caller's merge field |
| `No resume found for Job Applicant '...'.` | No PDF attached to that record | Confirm the resume was uploaded |
| `No PII strings to mask.` | Neither `mask_strings` nor the regex fallback found anything | Pass explicit `mask_strings` |
| `Unknown client_key '...'.` | Wrong/unregistered `client_key` | Register via `/clients/self-register` or check the Org Id |
| `watermark_base64 is not valid base64.` | Malformed inline watermark | Check the encoding |
| `resume_base64 is not valid base64.` | Malformed inline resume (`/mask/inline` only) | Check the encoding |
| `This org is already registered...` | `/clients/self-register` called twice | Rotate via `/admin/clients` instead |
| `Postgres isn't provisioned on this deployment (DATABASE_URL unset)...` | `DATABASE_URL` unset | N/A here — it *is* set; this fires only if it's later removed |
| `CLIENT_SECRET_ENCRYPTION_KEY is not set...` | Registry write attempted without the encryption key | **This is the current live blocker for self-register/admin — see §0** |
| `Missing or invalid X-Admin-API-Key.` / `Admin API not configured...` | Wrong/missing admin key | Set `ADMIN_API_KEY` |
